# 配送ルート作成マニュアル（スタッフ向け）

Google Sheets だけで配送ルートを作るための手順書です。ターミナルや専用ソフトは使いません。

この Google Sheets 完結版が普段の主な使い方です。プログラムやデータベース（Supabase）を
使わなくても、この手順だけで毎日の配送ルートを作れます。

このマニュアルの例はすべて匿名のサンプルです。実際の顧客名・住所・キーは書きません。
設定（APIキーやセンター住所）は管理者が事前に済ませています。設定手順は
[google_sheets_setup.md](google_sheets_setup.md) を参照してください。

## 1. 何をするツールか

配送先の住所を貼り付けると、住所を地図上の位置（緯度経度）に変換して、
会社センターを起点にした配送順を自動で作ります。

- 入力: 配送先の住所と優先度
- 出力: 配送日ごとの新しいシートタブ（例 `2026-08-16_配送ルート`）に、配送順・住所・距離
- 順番の決め方: 優先度が小さい配送先が先。同じ優先度なら、直前の地点から近い順
- 距離は直線距離の目安です。実際の道路距離・所要時間・渋滞は考慮しません。
  最終的な順番は担当者が確認・調整してください。

## 2. 事前に用意するCSV

受付書や Salesforce から書き出したCSVを使います。最低限、次の4列があれば動きます。

| 列 | 必須 | 内容 |
| --- | --- | --- |
| `id` | 任意 | 配送先の管理番号。空でも可（`D01` からの連番が入ります） |
| `name` | 任意 | 配送先名。空でも可（住所が名前として使われます） |
| `address` | **必須** | 住所。ここが空の行は無視されます |
| `priority` | 任意 | 優先度。1が最優先。空欄は `9`（一番後ろ）扱い |

見出しは日本語でも構いません（`住所` = `address`、`優先度` = `priority`、`配送先名` = `name`）。
任意で `time_window_start` / `time_window_end` / `service_minutes` も使えます。
列の詳しい仕様は [input_template.md](input_template.md) にあります。

CSVの例（匿名サンプル）:

```text
id,name,address,priority
,,東京都江東区有明3-11-1,1
,公共施設C,東京都新宿区西新宿2-8-1,2
D004,,東京都千代田区丸の内2-4-1,3
```

## 3. 配送先入力シートへの貼り付け方

1. スプレッドシートを開く
2. 下のタブから `配送先入力` シートを選ぶ
   （無ければメニュー `配送ルート > 配送先入力テンプレートを作成` で作れます。
   このメニューは配送日に今日の日付を入れます。既にあるシートで実行しても、
   貼り付け済みのデータは消さず、足りない配送日や見出しだけを足します）
3. 前回のデータが残っていれば、見出し行を含めて選択して削除する
4. CSVの中身を **見出し行ごと** コピーして、`配送先入力` シートに貼り付ける
   - Excel から貼るときは、そのまま貼り付ければ列に分かれます
   - テキストのCSVを1列にまとめて貼ってしまった場合は、`データ > テキストを列に分割` で分けます
5. `address` 列に住所が入っていることを確認する

貼り付け後のイメージ:

```text
        A        B          C                          D
1  配送日    2026-08-16
2  id        name       address                    priority
3            公共施設A   東京都江東区有明3-11-1        1
4                       東京都渋谷区神南1-19-8        2
5            公共施設C   東京都新宿区西新宿2-8-1       2
```

## 4. 配送日の入れ方

次のどちらか1つで指定します。

- **方法A（おすすめ）**: 見出し行より上の行に `配送日` と入力し、その **右のセル** に日付を入れる
- **方法B**: `delivery_date` という列を作り、その列に日付を入れる

日付は `2026-08-16` の形式が確実です（`2026/8/16` でも読み取れます）。
ここで入れた日付が、そのまま出力タブの名前になります。

## 5. 「配送ルート作成」の実行

1. 上部メニューの `配送ルート` をクリック
2. `配送ルート作成 (配送先入力シートから)` をクリック
3. 初回だけ Google アカウントの承認画面が出ます。内容を確認して許可してください
4. 実行中は画面上部に処理中の表示が出ます。件数が多いと1〜2分かかることがあります。
   終わるまでシートを閉じたり編集したりしないでください

## 6. 成功したとき

- `2026-08-16_配送ルート` のような **配送日の名前が付いた新しいタブ** ができ、そのタブが開きます
- タブの上部に起点・合計距離・配送先件数、その下に配送順の明細が入ります
- 画面下に `「2026-08-16_配送ルート」に ○件の配送順を作りました。` の通知が出ます
- 同じ日付でもう一度実行しても前のタブは消えません。`2026-08-16_配送ルート_2` のように連番が付きます
- 取得した緯度経度は `配送先入力` シートの `lat` / `lng` 列に書き戻されます（次回以降は再取得しません）

明細の列:

```text
配送順 | ID | 配送先名 | 住所 | 希望時間 | 作業分数 | 優先度 | 区間距離km | 累計距離km
```

## 7. よくあるエラーと対処

| メッセージ | 対処 |
| --- | --- |
| `「配送先入力」シートが見つかりません。` | シート名を `配送先入力` に直す（前後の空白や全角半角の違いに注意） |
| `住所が入った行がありません。` | `address`（または `住所`）列に住所が入っているか確認する |
| `見出し行が見つかりません。` | 見出し行（`id,name,address,priority` の行）ごと貼り付け直す |
| `配送日が分かりません。` | 4章のとおり `配送日` セルか `delivery_date` 列に日付を入れる |
| `未処理の住所が ○件残っているため、ルートは作っていません` | 1回で座標にできるのは80件までです。もう一度同じ操作を実行すると続きから処理され、全件そろった回にルートができます。途中までのルートは作られません |
| `座標を取得できた配送先がありません。` | 住所の表記を見直す（番地の記号、建物名だけになっていないか） |
| 通知に「取得できなかった住所」が出た | その住所はルートから外れています。表記を直して再実行してください |
| `スクリプトプロパティに GOOGLE_MAPS_API_KEY を設定してください。` | 管理者の設定が未完了です。管理者に連絡してください |
| `起点が設定されていません。` | 同上。センター住所の設定を管理者に依頼してください |
| `Google Geocoding API がエラーを返しました` | 同上。キーの設定・上限の問題です。管理者に連絡してください |

## 8. やってはいけないこと

- APIキーやパスワードをシートのセル・メモ・チャットに貼らない（設定は管理者が行います）
- `Code.gs` などスクリプトの中身を書き換えない
- 出力された `YYYY-MM-DD_配送ルート` タブを直接書き換えて配布しない
  （修正が必要なら `配送先入力` を直して作り直す）
- `配送先入力` シートの名前を変えない、見出し行を消さない
- 実行中に別の人が同じシートで実行しない（タブが二重にできます）
- できたルートをそのまま鵜呑みにしない。直線距離での目安なので、担当者が最終確認する

## 9. 困ったときは

エラーメッセージをそのままコピーして管理者に連絡してください。
このとき、顧客名や住所などの実データはスクリーンショットに入れないよう注意してください。

作った人がいなくなっても、この仕組みは Google Sheets と Apps Script だけで動いています。
スクリプトや設定の内容はリポジトリにすべて残してあるので、引き継ぎで困った場合は
管理者向けの [admin_setup.md](admin_setup.md) と、運用の考え方をまとめた
[operation_decisions.md](operation_decisions.md) を見てください。

スタッフが自分で判断してよいこと・管理者に回すこと:

| 状況 | 対応 |
| --- | --- |
| 住所の表記ミス、見出し行の貫り付けミス | スタッフが直して再実行してよい |
| 順番を少し入れ替えたい | 優先度を直して作り直すか、現場で担当者が調整する |
| キー・起点・上限に関するエラー | 管理者に連絡（スタッフ側では直さない） |
| 機能を変えたい・不具合が続く | 管理者に連絡し、GitHub の Issue に残してもらう |
