# 管理者セットアップ手順

Google Sheets 完結版（段階3）と Supabase 連携（段階2）を使えるようにするための、
管理者が最初に1回だけ行う作業です。スタッフの操作手順は [staff_manual.md](staff_manual.md)、
Sheets 側の全体像は [google_sheets_setup.md](google_sheets_setup.md) を参照してください。

主運用は Google Sheets + Apps Script（段階3）です。ここだけ設定すれば日々の運用は回ります。
Supabase（段階2）は必須ではなく、履歴保存・分析・Web化が必要になったときだけ設定します
（方針の背景は [operation_decisions.md](operation_decisions.md)）。

このドキュメントに実際のキー・URL・住所は書きません。すべてスクリプトプロパティに入れます。

## 1. Code.gs の貼り替え

1. 対象のスプレッドシートを開く
2. `拡張機能 > Apps Script` を開く
3. エディタの `コード.gs`（`Code.gs`）を開き、**中身をすべて選択して削除**する
4. リポジトリの `apps-script/Code.gs` の中身をすべてコピーして貼り付ける
5. 保存する（`Ctrl` / `Cmd` + `S`）
6. スプレッドシートを開き直す。メニューに `配送ルート` が出れば成功

注意:

- ファイルを増やさず、1ファイルを丸ごと置き換えてください（関数の一部だけを貼ると壊れます）
- 貼り替え後は必ずスプレッドシートを開き直してください（`onOpen` はシートを開いた時に走ります）
- 初回実行時に Google アカウントの承認画面が出ます。許可すると以後は出ません
- 更新した Code.gs を配る場合、スタッフの各スプレッドシートで同じ貼り替えが必要です
  （複数運用するなら、テンプレートのスプレッドシートをコピーして配る運用が楽です）

## 2. スクリプトプロパティの設定

Apps Script エディタの左下 `プロジェクトの設定（歯車）> スクリプト プロパティ > スクリプト プロパティを追加`
から登録します。

| プロパティ名 | 用途 | 必須 |
| --- | --- | --- |
| `GOOGLE_MAPS_API_KEY` | 住所の座標化（段階3） | 段階3で必須 |
| `ROUTE_ORIGIN_ADDRESS` | 会社センターの住所。実行時に座標化される | 下の LAT/LNG とどちらか必須 |
| `ROUTE_ORIGIN_LAT` / `ROUTE_ORIGIN_LNG` | 会社センターの座標。設定すると座標化を省ける | 上の ADDRESS とどちらか必須 |
| `ROUTE_ORIGIN_NAME` | 起点の表示名。未設定なら `会社センター` | 任意 |
| `SUPABASE_URL` | Supabase の Project URL（段階2） | 段階2で必須 |
| `SUPABASE_ANON_KEY` | Supabase の anon public キー（段階2） | 段階2で必須 |

段階3（Sheets 完結版）だけを使うなら、Supabase の2つは不要です。

設定漏れは実行時に次のメッセージで分かります。

```text
スクリプトプロパティに GOOGLE_MAPS_API_KEY を設定してください。
起点が設定されていません。スクリプトプロパティに ROUTE_ORIGIN_ADDRESS (または ROUTE_ORIGIN_LAT と ROUTE_ORIGIN_LNG) を設定してください。
スクリプトプロパティに SUPABASE_URL と SUPABASE_ANON_KEY を設定してください。
```

## 3. GOOGLE_MAPS_API_KEY の扱い

作り方:

1. Google Cloud Console でプロジェクトを選ぶ（社内用の請求先が紐づいたもの）
2. `APIとサービス > ライブラリ` で **Geocoding API** を有効にする
3. `APIとサービス > 認証情報 > 認証情報を作成 > APIキー` でキーを作る
4. 作ったキーを `GOOGLE_MAPS_API_KEY` としてスクリプトプロパティに貼る

守ること:

- `Code.gs` に直書きしない。シートのセル・チャット・スクリーンショットにも出さない
- リポジトリにコミットしない（`.env` は `.gitignore` 済み）
- スクリプトプロパティは **そのスプレッドシートの編集権限を持つ人が見られます**。
  編集者は必要な人だけに絞ってください（閲覧者は見られません）
- キーが漏れた疑いがあるときは、Cloud Console でキーを削除して作り直し、
  スクリプトプロパティを新しい値に差し替えます

## 4. APIキーの制限

キーを作ったら、そのまま使わず必ず制限をかけます（`認証情報 > 該当キー > 編集`）。

- **APIの制限**: `キーを制限` を選び、**Geocoding API のみ**にチェック
- **アプリケーションの制限**: Apps Script からの呼び出しは Google のサーバー経由で
  発信元IPが固定されないため、IP制限・HTTPリファラー制限は使えません。
  実質は「APIの制限」と後述の割り当て・予算で守ります
- 用途ごとにキーを分ける（段階3用のキーを他のサービスと共用しない）。
  漏洩時に影響範囲を切りやすくなります
- `APIとサービス > 割り当て` で Geocoding API の1日あたりリクエスト数に上限を設定し、
  想定外の使用量を止められるようにします

## 5. Supabase を使う場合（段階2）

段階2でルート履歴を Sheets に表示する場合のみ設定します。

1. Supabase の SQL Editor で `supabase/schema.sql` を実行する（ビューと grant の反映に必要）
2. `Project Settings > API` から次の2つを取得する
   - Project URL → `SUPABASE_URL`
   - `anon public` キー → `SUPABASE_ANON_KEY`
3. スクリプトプロパティに登録する

Apps Script が読むのは `latest_route_stops` / `latest_route_summary` の2ビューだけで、
元テーブルは RLS 有効かつ anon から revoke 済みです。

### service_role キーは Apps Script に置かない

`SUPABASE_SERVICE_ROLE_KEY` は RLS を無視して全テーブルを読み書きできる管理者キーです。
**スクリプトプロパティにも Code.gs にも絶対に置かないでください。**
スクリプトプロパティはスプレッドシートの編集者が閲覧できるため、
置いた時点で編集者全員にデータベースの全権限を渡すのと同じになります。

service_role キーを使ってよいのは次だけです。

- 管理者の手元PC（`.env` / 環境変数）で実行する取り込み・保存スクリプト
- Fly.io の secrets に登録したバッチ実行

Sheets 側は anon キーによる読み取り専用に固定します。

## 6. API費用と予算アラート

Geocoding API は従量課金です。座標は `配送先入力` シートの `lat` / `lng` に書き戻され、
2回目以降は再問い合わせしないため、通常は「新しく増えた住所の件数」だけ課金されます。
1回の実行で問い合わせるのは最大80件です。

確認しておくこと:

1. `お支払い > 予算とアラート` で月次予算を作り、50% / 90% / 100% のメール通知を設定する
2. `APIとサービス > Geocoding API > 指標` で、月の実リクエスト数を定期的に確認する
3. `APIとサービス > 割り当て` で1日あたりの上限を入れ、事故があっても青天井にならないようにする
4. 最新の単価と無料枠は Google の料金ページで確認する（改定されることがあります）

想定より件数が伸びている場合は、同じ住所を毎回貼り直していないか（`lat` / `lng` を消していないか）を
スタッフの運用と併せて確認してください。

## 7. 設定後の動作確認

実データを使う前に、匿名サンプルで確認します（実データでの確認は社内の Google Workspace 上で行います）。

1. `配送先入力` シートに次を貼る

```text
配送日   2026-08-16

id,name,address,priority
,,東京都江東区有明3-11-1,1
,公共施設C,東京都新宿区西新宿2-8-1,2
```

2. メニュー `配送ルート > 配送ルート作成 (配送先入力シートから)` を実行する
3. `2026-08-16_配送ルート` タブができ、`lat` / `lng` が書き戻されていれば設定完了
4. もう一度実行して `2026-08-16_配送ルート_2` ができること（上書きされないこと）も確認する

過去の確認記録は [test_evidence_sheets_stage3.md](test_evidence_sheets_stage3.md) にあります。

## 8. 担当者が交代しても続けられるように

この仕組みは、作った人や外部のツールが使えなくなっても、次の3つがあれば運用を続けられます。

1. 対象のスプレッドシート（社内 Google Workspace）
2. このリポジトリの `apps-script/Code.gs`
3. スクリプトプロパティの値（キーと起点。値は社内のパスワード管理で保管）

引き継ぎ時に確認すること:

- Google Cloud プロジェクトの請求先と、予算アラートの送信先メールを新しい担当者に向ける
- スプレッドシートのオーナーと編集者を見直す（編集者はスクリプトプロパティを見られます）
- 退職・異動した人が作った API キーは作り直す
- 変更履歴と未着手の課題は GitHub のコミットと Issue に残す

コードを直す場合の最低限の手順:

1. GitHub で新しいブランチを作り、`apps-script/Code.gs` を編集して PR を出す（`main` を直接変更しない）
2. 手元に Node.js があれば `node apps-script/tests/code_test.js` でロジックを確認する
   （外部通信なしで実行できます）
3. マージ後、本書1章の手順でスプレッドシートの Apps Script に貼り替える
4. 匿名サンプルで本書7章の確認をやり直す
