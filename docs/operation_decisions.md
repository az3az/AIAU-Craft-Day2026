# 運用方針の決定事項

このリポジトリを社内で運用していくうえで決めたことをまとめます。設計の詳細ではなく、
「何を主に使い、何を今は使わないか」「どこまでを外部ツールにやらせるか」の判断を残す場所です。

方針を変えたときは、この文書を更新してから作業してください。

## 1. 主運用は Google Sheets + Apps Script

当面の運用は Google Sheets と Apps Script（`apps-script/Code.gs` の段階3）を主とします。

理由:

- 配車担当・ドライバーがターミナルや開発環境を使わずに操作できる。
- 追加のサーバーやアカウント管理が不要で、社内の Google Workspace の権限管理に乗せられる。
- 結果をそのまま共有・手修正できる。

運用の入口:

- 操作手順: [staff_manual.md](staff_manual.md)
- 入力シートの列仕様: [input_template.md](input_template.md)
- 管理者の初期設定: [admin_setup.md](admin_setup.md)

Python の CLI（`src/` 配下）は廃止しません。まとまった件数の処理や検証用として残します。

## 2. Supabase は必須にしない

Supabase は現時点では必須構成要素ではなく、次のいずれかが必要になった段階で使います。

- 過去ルートの履歴保存と参照
- 配送実績の集計・分析
- Google Sheets 以外（Web画面など）からの参照

それまでは Google Sheets 完結版に Supabase 書き込みを追加しません。スキーマ
（`supabase/schema.sql`）と Python 側の取り込み・保存スクリプトは残し、必要になったときに使える状態を保ちます。

判断は Issue で継続検討します（Supabase履歴保存の再検討）。

## 3. Devin の使い方

- Devin は実装とPR作成に使います。作業は必ず新しいブランチで行い、`main` に直接変更しません。
- PRは作成してよいですが、こちらが確認するまでマージしません。
- Devin には実データ・秘密鍵を渡しません。具体的には次を共有しません。
  - `GOOGLE_MAPS_API_KEY`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_ANON_KEY`、`FLY_API_TOKEN`
  - 実顧客名・実スタッフ名・実住所を含む受付書やスケジュール表
  - 実スプレッドシートのURL、実データが映ったスクリーンショット
- そのため Devin 側での検証は、匿名の公共施設サンプルとスタブを使ったロジックテスト
  （`node apps-script/tests/code_test.js`）までとします。

## 4. 実データでの検証は社内 Google Workspace 上で行う

実データを使った確認は、社内アカウントの Google Workspace（社内のスプレッドシートと
Apps Script プロジェクト）で担当者が行います。

- 実行結果はスクリーンショットや実URLではなく、件数・合計距離・作成されたタブ名など
  公開しても問題のない形にしてから記録します。
- 記録の置き場所はリポジトリ内の動作確認記録
  （例: [test_evidence_sheets_stage3.md](test_evidence_sheets_stage3.md)）。
- 実データそのもの、APIキー、社内固有の住所はリポジトリに置きません。社内メモ側で管理します。

## 5. レビューと運用判断は Codex / GPT を併用する

- 生成されたコードのレビュー、仕様の妥当性チェック、運用上の判断整理には Codex / GPT を使います。
- ただし、レビュー時も実データ・秘密鍵は入力しません。共有するのは公開リポジトリに置いてある
  コードとドキュメントの範囲に限ります。
- 最終的な採否の判断は担当者が行い、決めたことはこの文書か Issue に残します。

## 6. 変更してはいけない前提

- `SUPABASE_SERVICE_ROLE_KEY` を Apps Script やフロント側に置かない。
- APIキー・トークンをコード、シート、リポジトリに書かない（スクリプトプロパティまたは環境変数）。
- 実データや実会社の Excel をリポジトリにコミットしない。サンプルは匿名のみ。
